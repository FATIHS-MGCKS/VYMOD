# Internationalization Standard

## Locales

Initial: `de-DE` (primary product language), `en-US`. Architecture must not assume German-only UI.

## Rules

1. All user-visible strings use translation keys in `i18n/locales/`.
2. No hardcoded UI copy in application code (when present).
3. Errors, validation, onboarding, notifications, accessibility labels included.
4. Keys must exist in **both** locale files; CI enforces parity.
5. Placeholders must match across locales (`{name}`, `{count}`, ICU plurals documented in ADAPTER).
6. Locale-aware date, time, number, unit formatting; store UTC timestamps.
7. Language preference independent of km/mi preference.
8. Layouts tolerate future RTL.
9. Missing translations **fail CI** — no silent English fallback in production builds.
10. Legal disclosures: separate keys + `legalReviewStatus` metadata when introduced.

## Validation

`npm run validate:i18n` — see `i18n/ADAPTER.md`.
